Client-first work policy, step 3 of 3 (issue #136, ADR 0012): the bug gate is now enforced at the seam, and the dashboard's live state refreshes on a documented cadence. Every issue-agent start re-checks the client policy server-side — the target issue resolves through the host's own gh, the open client-bug set revalidates with a bounded live label read immediately before the spawn, and validated prerequisites are real blocker edges whose blocked side is a live-open client bug. Denials are typed (`client_bugs_open` with repository-scoped blocking references, `client_priority_unverified`, `target_not_open`), carry 403 status, release the claimed engine slot, and render in the agent panel with the blocking tickets spelled out; PR reviews stay ungated, and unknown, closed, or unclassifiable targets fail closed. The shared workflow atom gains a refresh lifecycle: coalesced ~60s polling while the tab is visible (backing off to five minutes on errors, stopping in static mode), an immediate re-read on tab focus, and a header chip showing the last successful check or the retrying state — slow or foreign-repo answers never overwrite newer state. The gh issue-view normalization is shared by both seam surfaces.
