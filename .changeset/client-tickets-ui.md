Client-first work policy, step 2 of 3 (issue #136, ADR 0012): the Client Tickets surface and client-aware ranking. New `/client-tickets` view beside Overview — every open client ticket by default (not just the executable frontier), with URL-backed filters for Bugs / Feedback & requests / All, ownership, waiting/blocked, and text search; the shared issue detail panel deep-links via `?issue=NN`; unfiltered open totals stay visible behind any filter; issue age and last update render as plain data, never an SLA; a Closed lens reads a bounded, label-specific history (one page per label, most recently updated first) through the new `GET /api/client-tickets/closed` seam read, naming completed and not-planned closures as GitHub does. The shell grows persistent open-client counts (distinct bug count) in the header, a badge on the nav entry, and a persistent banner while any client bug is open — "new feature starts paused" — on every page, in text and icon, never color alone. The Overview gains a Client attention section above ordinary work with ownership and waiting/blocked explanations; the recommendation engine reads a `client-action` bucket first (remediation for grabbable ready client bugs, triage for untriaged ones — waiting client work is attention, never a recommendation); triage lanes, in-flight lists, and the frontier strip sort client tickets ahead of internal work. Unknown or incomplete client coverage renders as a visible warning everywhere — never a quiet zero.
